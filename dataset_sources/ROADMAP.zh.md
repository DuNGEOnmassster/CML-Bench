# CML-Bench 数据扩建：从单一电影语料转向跨媒介叙事数据

调查日期：2026-10-12。目标：**全球公开发布，尽量支持训练与评测；新增语料不来自 MovieSum。**
这里区分实际实现、候选来源和后续验收任务，不把目录条数当作已发布数据量。

## 为什么不能只讨论“1.2 万条够不够”

1.2 万条可用于有价值的评测；它是否足够取决于独立作品、难度、统计功效和覆盖。
同一部电影切成十段不会带来十个独立故事，增加切片也不能弥补电影类型、语言、年代、
国家和媒介的偏差。用于大规模训练时，1.2 万条通常只能视作特定任务的起点，不能据此
宣称通用叙事能力覆盖。新版本必须同时报告作品、版本、作者、故事族、片段、字符/token、
来源和权利核清数量，并按作品/故事族计算置信区间。

本次代码已实现这些数量的基础分离、目录采集、授权记录检查、保留类型的本地文本准备、
精确去重及故事族划分；没有完成新模型实验、全量权利核查或全文数据发布。

## 来源地图与获取优先级

详细字段、原始政策链接与检查日期见 [registry.json](registry.json)。它是可继续维护的
来源地图，不声称穷尽互联网上所有合法渠道，也不等于 25 个都可直接下载的开放全文库。

| 路线 | 候选来源 | 具体价值 | 首要约束 |
|---|---|---|---|
| 公版小说/故事 | Gutenberg、Standard Ebooks | 大量英文及多语种长篇、故事、戏剧 | 美国公版不等于全球公版；同一作品多版本重复 |
| 多语种策展小说 | ELTeC | 按语言与年代整理的长篇，结构较清楚 | 每个子库/底本及文本与标记许可分开核实 |
| 多语种舞台剧 | DraCor、TextGrid、DTA | 显式角色、台词、舞台指示、幕场、TEI | DraCor 子库许可有例外；不能直接套平台 CC0 |
| 亚洲与多语种文本 | 中文及各语种 Wikisource、Aozora | 中文、日文等覆盖，扫描与校对可追溯 | 原作、译者、现代整理者及当地公版认定分开 |
| 开放电影项目 | Blender Studio | 真实现代短片创作资料，可能含原始剧本 | 必须确认具体剧本资产；电影/字幕不等于剧本 |
| 权利人直供 | 独立编剧、电影学院、剧团、小说作者 | 补充现代题材和此前未公开的故事 | 明确全球公开许可、共同权利人、底本及改编权 |
| 馆藏发现 | LoC、Internet Archive、Gallica、HathiTrust | 老电影、早期小说戏剧、扫描/目录线索 | 每件权利和数字化访问条款；不采借阅/DRM资源 |
| 学术数据存储 | Zenodo、OSF | 找到有 DOI/版本的文学、戏剧研究语料 | 存储平台的开放标签不替上传者清理底层版权 |
| 作品关系元数据 | Wikidata、Open Library、Europeana | 原作—电影—舞台改编、作者、译本、版本关系 | 元数据许可不能授权全文；优先官方 API/批量导出 |
| 仅授权后考虑 | IMSDb、DailyScript、SimplyScripts、Folger | 电影剧本线索、作者联系线索、编辑质量 | 可阅读/教育用途或 NC 许可不足以进入默认开放训练集 |
| 不采集 | Script Slug；MovieSum | 前者现行条款限制自动采集，后者明确不在本轮范围 | 代码中的排除策略不可被一个 approved 字段绕过 |

尤其不能把 Folger Shakespeare 的“莎士比亚已过保护期”误读成现代编辑版本不受条件限制；
也不能把 LoC/Internet Archive 的可看电影或 ASR 字幕计为人类编写的电影剧本。
现代电影全文是最难合法扩大的部分，应为授权和作者合作单列资源，不能拿小说数替代它。

## 保留三个原生轨道，另设改编任务

| 轨道 | 原始文本单位 | 可构建任务 | 禁止混淆 |
|---|---|---|---|
| Screenplay | 人类编写的电影/短片剧本、场景、角色和对白 | 摘要到剧本、续写、修订、人物与因果一致性 | 字幕、影片转录、AI 小说改写不能冒充原始剧本 |
| Stage play | 幕、场、对白、舞台指示 | 场景生成、角色声音、舞台可执行性、跨场一致性 | 舞台提示与电影镜头语言分别评价 |
| Novel / prose fiction | 章、段落、叙述、对话 | 情节规划、长程依赖、视角、人物一致性、续写 | 小说不能强行套对白密度/场景标签指标 |
| Adaptation（派生任务） | 已核清的小说/戏剧与改编目标 | 小说→电影、戏剧→电影，保留角色/事件约束 | 只有真实已授权配对才能称人类改编参考；AI目标必须标记 synthetic |

先采完整作品并建身份关系，再切片。`work_id` 归并不同版本与翻译；`story_family_id`
归并原作、改编、重拍和相关故事。媒体类型、作品版本、翻译状态都不得由标题猜测后直接
当作真值。目录启发式分类只是候选筛选，保留人工复核队列。

## 规模与验收：目标不是已获得数量

以下为**分阶段规划目标**，不是法律可获得性承诺，也不是本 PR 已完成的数据量：

| 阶段 | 建议目标 | 放行条件 |
|---|---|---|
| 目录普查 | ≥30,000 条非 MovieSum 候选记录；明确原作去重尚未完成 | 每个来源有抓取记录、缓存哈希、错误清单和权利待核状态 |
| 权利/解析试点 | 300 个独立作品；三个原生轨道均有样本 | 逐作品权利依据；双人核查权利样本；文本保真及版本匹配通过 |
| 首个可公开语料版 | 5,000 个独立作品、30,000–100,000 个自然片段，逐步到 ≥5 种语言 | 不靠单一来源或少数作者填满；各轨道独立报告，缺口公开 |
| 现代电影补充 | 首批争取 100 个真实独立电影/短片剧本 | 获得合适的直接许可；未实现时不能以小说替代达标 |
| 独立评测集 | 1,000 个故事族、约 3,000–5,000 个高质量任务 | 与训练语料及旧 GT 相关作品隔离；人类复核；每轨道统计功效分析 |
| 后续训练扩展 | 权利和质量允许时再向 10,000+ 作品、100,000+ 片段推进 | 根据新增独立作品/题材收益决定，不能只看 token/切片增长 |

若现代电影许可不足，优先诚实发布多轨道文学/戏剧语料及少量 screenplay 子集；
保留 CML-Bench 的电影主指标，另报迁移结果，不将扩大后的全部条数称为电影剧本数量。

## 按顺序推进的数据工作

### A. 来源、身份与权利

- **已实现**：25 路来源登记、三个文学目录连接器与可选的 Wikidata 电影改编元数据连接器、
  来源与版本计数、原始响应校验哈希。电影元数据不能当作已获得的电影剧本。
- **已实现**：显式逐资产权利记录，original/edition/translation 分层，默认拒绝未知、
  NC/ND、地区不全及仅元数据许可；MovieSum 排除；排除名单缺失报错。
- **待完成**：逐作品权利证据审查；归并 Wikidata/Open Library/IMDb 等身份；
  原作与改编图；作者直供协议与适当激励。不能用 grant 模板冒充已获授权。
- **验收**：公开文本的每一行均可追溯具体资产、版本、权利层与证据；持有并保留必要署名。

### B. 下载、转写与结构保真

- **已实现**：本地授权资产 SHA-256 校验，TEI/CML/纯文本解析，结构和位置保留，
  不重叠分块，超长/过短片段记录，模糊结构拒绝，拒绝无明确角色的剧本纯文本导入。
- **待完成**：按来源实现授权全文连接器；EPUB reading-order 导入、PDF 布局解析、
  OCR 置信度；支持更多真实 TEI 变体，抽样逐页/逐行对齐。
- **验收**：每个语言×来源×格式分层抽样；区分文本增删、角色错配、旁白混入对白、
  漏页、前后场连接错误；零错误不能仅凭正则扫描宣称。

### C. 去重、划分与污染控制

- **已实现**：精确规范化全文去重，原作/故事族/已登记改编连通分量划分；
  相关作品排除传递；按作者跨 split 统计；可版本化的完整输出哈希。
- **待完成**：MinHash/近重复、章节重用、译本跨语种和系列关系审查；作者留出集；
  冻结最终 train/dev/test；将旧 GT-100 与其关系图加入排除台账。
- **验收**：同一原作、译本、重拍/改编不跨训练测试；按故事族而不是片段 bootstrap；
  发布重复/关系检查报告，明确经典作品预训练污染仍无法仅靠划分排除。
- 对新近委托/授权的未公开作品设独立新颖性子集，记录首次公开日期和模型知识截止；
  避免把“与旧 GT 不同”叫作无污染。

### D. 标注与任务

- 将 synopsis、事件链、角色表、人物状态、因果依赖、时间线、视角、场景边界、
  source-grounded supporting spans 分开存储，并附 annotator、模型版本和成本。
- 自动摘要必须由不同角色复核，gold 子集需人工审查；保留争议、修订与依据。
- 先做 100–300 作品跨媒介试点，校准错误类型及长度规则，再扩大；不对几万候选
  直接启动多 agent 重写。允许一份文本服务多个任务，但不能虚增独立作品数。
- 给任务明确输入/输出和可接受解：同一摘要可能有多种合理剧本，不能仅用参考文本
  相似度判断创造性质量。counterfactual/扰动任务需标记合成来源和可验证修改。
- **验收**：所有 gold 标注有支持文本、质量状态和复核记录；分层错误率及区间公开。

### E. Benchmark 实验与发布

- 原评测代码仍是旧 screenplay runner；先解决论文九指标与代码八指标的差异，
  再设计电影、舞台、小说各自适用的指标与共同叙事维度。
- 测试摘要→生成、受约束续写、长程依赖修复、真实授权改编四类任务，提供基线、
  输入长度预算、推理配置、随机种子、失败率、成本及按轨道/语言的结果。
- 建立人类评分子集，报告模型内/组内相关性和评审一致性；避免混合易分的组别
  获得较高整体相关性却没有组内区分能力。
- 不把 agent 审计称作专家人工审计。抽样必须区分随机样本与定向样本，给出有效
  独立作品数、置信区间和失败标准。
- 最终发布数据卡、版本 DOI、来源/权利/署名 manifest、split、排除台账、哈希、
  采集与标注日志，以及纠错/移除流程。全文许可与仓库 MIT 代码许可分开。

## 成本控制与收益衡量

先目录→身份/权利→解析试点→试标→冻结标准→分批扩展。每一阶段记录每新增独立作品、
每个合格片段和每个 gold 任务的成本。摘要使用 content hash + prompt version 缓存；
仅在内容或标准发生实质改变时重写。不要为了词数分布反复重做全部摘要。

新来源是否值得继续，以“新增独立作品和语言/体裁覆盖 × 质量通过率 ÷ 获取及审查成本”
作排序线索，配合权利准入条件；该排序不替代人工取舍，也不伪造精确收益估计。
本 PR 的目录采集、解析测试均不调用收费语言模型。

## 与既有工作如何衔接

PR #1–#4 的大规模清洗、逐批审计、版本复用有工程价值，但原有来源与默认许可条件
不自动满足此次目标。当前 PR 从 `main` 独立新增 `dataset_sources/`，避免强依赖未合并
的 Cursor 云端运行目录。旧集作为对照和排除依据；新轨道拥有独立的来源、权利、身份、
格式和评价协议，不以添加一个数据下载链接宣称完成新版 benchmark。
